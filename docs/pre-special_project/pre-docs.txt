2. รายละเอียดโครงงาน
	2.1 ความเป็นมาและความสำคัญของปัญหา
	การเรียนการสอนในภาควิชาเทคโนโลยีสารสนเทศมีความจำเป็นต้องใช้ระบบปฏิบัติการลีนุกซ์ในหลายรายวิชา โดยเฉพาะในรายวิชาที่เกี่ยวข้องกับระบบเซิร์ฟเวอร์ การพัฒนาแอปพลิเคชัน และการจัดการโครงสร้างพื้นฐานด้านไอที อย่างไรก็ตาม การเตรียมสภาพแวดล้อมสำหรับการใช้งานระบบลีนุกซ์นั้นมักมีความยุ่งยากและใช้เวลานาน ทั้งในด้านการติดตั้ง การตั้งค่า และการจัดการทรัพยากร ส่งผลให้การเรียนการสอนไม่สามารถดำเนินไปได้อย่างเต็มประสิทธิภาพ
	ที่ผ่านมา นักศึกษาและอาจารย์ต้องใช้วิธีการจำลองระบบลีนุกซ์ผ่านเครื่องเสมือน (Virtual Machine), ระบบย่อยของวินโดว์สำหรับลีนุกซ์ (WSL), หรือบริการคลาวด์จากภายนอก ซึ่งแต่ละวิธีมีข้อจำกัด เช่น ความยุ่งยากในการตั้งค่า ความไม่เสถียรของระบบ หรือค่าใช้จ่ายเพิ่มเติมในการใช้งานบริการจากผู้ให้บริการภายนอก โดยเฉพาะในการทำโครงงานที่ต้องใช้เซิร์ฟเวอร์ นักศึกษามักต้องจัดหาเครื่องคอมพิวเตอร์ส่วนตัวหรือเซิร์ฟเวอร์ด้วยตนเอง ซึ่งเป็นภาระทั้งด้านเวลาและงบประมาณ
	เพื่อแก้ไขปัญหาดังกล่าวข้างต้น โครงงานนี้จึงมีแนวคิดในการพัฒนาแพลตฟอร์มคลัสเตอร์ภายในภาควิชา โดยใช้เทคโนโลยี Virtualization ร่วมกับระบบ cloud-Init เพื่อสร้างเครื่องจำลองลีนุกซ์ที่สามารถใช้งานได้อย่างรวดเร็วและง่ายดาย พร้อมทั้งมีระบบ Web Application สำหรับการจัดการและเข้าใช้งานเครื่องเสมือน ทั้งในส่วนของนักศึกษาและอาจารย์


	2.2 วัตถุประสงค์ของการจัดทำโครงงานพิเศษ
2.2.1 เพื่อออกแบบและพัฒนาแพลตฟอร์มคลัสเตอร์เสมือน (Virtual Cluster Platform) ที่สามารถสร้างและจัดการเครื่องเสมือนลีนุกซ์ได้อย่างรวดเร็วและมีประสิทธิภาพ สำหรับสนับสนุนการเรียนการสอนและการทำโครงงานในภาควิชาเทคโนโลยีสารสนเทศ
2.2.2 เพื่อพัฒนา Web Application แบบ Role-Based Access Control (RBAC) ที่รองรับการใช้งานของทั้งนักศึกษาและอาจารย์ ในการร้องขอ จัดการ และเข้าถึงเครื่องเสมือน โดยคำนึงถึงความง่ายในการใช้งาน เสถียรภาพของระบบ และความปลอดภัยในการเข้าถึง
2.2.3 เพื่อเพิ่มประสิทธิภาพการใช้ทรัพยากรเซิร์ฟเวอร์ที่มีอยู่ภายในภาควิชา ผ่านการพัฒนาระบบคลัสเตอร์แบบรวมศูนย์ ที่สามารถติดตาม วิเคราะห์ และบริหารจัดการทรัพยากรได้อย่างเหมาะสม โดยมีระบบ Monitoring และ Cloud Storage ที่สามารถรองรับการใช้งานในลักษณะ multi-user environment

	2.4.1  สมมติฐาน หรือ ข้อตกลงเบื้องต้นในการจัดทำโครงงานพิเศษ (Assumption of the Study)
		โครงงานพิเศษนี้ตั้งอยู่บนสมมติฐานว่า การพัฒนาแพลตฟอร์มคลัสเตอร์ภายในภาควิชาเทคโนโลยีสารสนเทศจะสามารถช่วยลดข้อจำกัดในการจัดเตรียมและใช้งานระบบปฏิบัติการลีนุกซ์สำหรับการเรียนการสอนและการทำโครงงาน โดยระบบที่พัฒนาขึ้นจะต้องสามารถสร้างเครื่องเสมือนลีนุกซ์ได้อย่างรวดเร็ว มีความเสถียร และสามารถใช้งานได้ตลอด 24 ชั่วโมง
       	ระบบดังกล่าวจะต้องรองรับการใช้งานของนักศึกษาและอาจารย์ได้ตามจำนวนทรัพยากรที่มีอยู่ในภาควิชา พร้อมทั้งมีระบบ Web Application ที่ใช้งานง่ายสำหรับการร้องขอและจัดการเครื่องเสมือน รวมถึงระบบเสริม เช่น ระบบ Reverse Proxy สำหรับการเข้าถึงเครื่องเสมือนจากภายนอก ระบบ Cloud Storage สำหรับการจัดเก็บไฟล์ และระบบ Monitoring สำหรับตรวจสอบสถานะของระบบทั้งหมด
	นอกจากนี้ ยังมีสมมติฐานว่าเครื่องเซิร์ฟเวอร์ที่มีอยู่ในภาควิชาสามารถนำมาใช้เป็นทรัพยากรหลักในการให้บริการระบบคลัสเตอร์ และสามารถติดตั้งซอฟต์แวร์ต่าง ๆ ที่จำเป็น เช่น Hypervisor, Container Orchestration, Web Application และระบบจัดการฐานข้อมูล เพื่อให้สามารถพัฒนาและใช้งานระบบได้อย่างมีประสิทธิภาพ
 	2.4.2 คำจำกัดความ (Key Word) 
	2.4.2.1 “Virtualization Technology” คือ เทคนิคที่ใช้ในการสร้างสภาพแวดล้อมจำลองบนระบบคอมพิวเตอร์ โดยสามารถแบ่งทรัพยากรออกเป็นส่วนเล็ก ๆ เพื่อให้แต่ละส่วนทำงานได้อิสระ
	2.4.2.2 “Web Application” คือ โปรแกรมหรือแอปพลิเคชันที่ถูกพัฒนาขึ้นเพื่อใช้งานผ่านเว็บบราวเซอร์ ทำให้สามารถเข้าถึงได้ง่าย
	2.4.2.3 “Cloud-Init” คือ เทคนิคการตั้งค่าเครื่องเสมือนโดยใช้ไฟล์ตั้งค่าที่เตรียมไว้ล่วงหน้า
	2.4.3 เนื้อหา เหตุผล และทฤษฎีที่สำคัญ
	2.4.3.1 Virtualization Technology
		Virtualization Technology เป็นการจำลองซอฟต์แวร์หรือฮาร์ดแวร์บนซอฟต์แวร์อื่น โดยสภาพแวดล้อมจำลองนี้เรียกว่าเครื่องเสมือน (Virtual Machine) ซึ่งมีการจำลองหลายรูปแบบโดยแยกตามชั้นสถาปัตยกรรมคอมพิวเตอร์ (ที่มา: Guide to Security for Full Virtualization Technologies)
		2.4.3.2 Cloud Computing
		Cloud Computing เป็นการประมวลผลแบบคลาวด์รูปแบบหนึ่งที่ช่วยให้สามารถเข้าถึงทรัพยากรการประมวลผลที่กำหนดค่าได้ตามต้องการ ซึ่งสามารถจัดเตรียมและปล่อยทรัพยากรได้อย่างรวดเร็วโดยใช้ความพยายามในการจัดการหรือการโต้ตอบระหว่างผู้ให้บริการน้อยที่สุด (ที่มา: Cloud Computing Technology The Architecture Overview)
	2.4.3.3 Web Application
		Web Application คือการพัฒนาระบบงานบนเว็บ ข้อมูลต่าง ๆ ในระบบสามารถเข้าถึงได้ทั้งเครือข่ายภายในหรือเครือข่ายสาธารณะ ซึ่งทำใช้งานง่ายผ่านเว็บบราวเซอร์ โดยในการใช้งานนั้นไม่จําเป็นต้องติดตั้งโปรแกรมใด ๆ เพิ่มเติม (ที่มา: Progress Tracking System for Special Project Documents)
	2.4.3.4 Reverse Proxy
		Reverse Proxy คือตัวกลางที่ส่งข้อมูลเครือข่ายที่แลกเปลี่ยนข้อมูลระหว่างไคลเอนต์และเซิร์ฟเวอร์ โดยจะรับคำขอจากไคลเอนต์บนเครือข่ายสาธารณะ (อินเทอร์เน็ต) ส่งต่อคำขอไปยังเซิร์ฟเวอร์ในเครือข่ายภายใน จากนั้นจึงส่งคำตอบที่สร้างโดยเซิร์ฟเวอร์ไปยังไคลเอนต์ และยังสามารถแคชทรัพยากรอินเทอร์เน็ตเพื่อให้ใช้ข้อมูลซ้ำได้ (ที่มา: An Extensible Universal Reverse Proxy Architecture)
	2.4.3.5 Container
		Container คือการรวมแอปพลิเคชันและรหัสไบนารี ไลบรารี และการกำหนดค่าเข้าด้วยกันในขณะที่แบ่งปันอิมเมจระบบปฏิบัติการโฮสต์ ดังนั้นคอนเทนเนอร์จึงแบ่งปันทรัพยากรและดำเนินการไมโครเซอร์วิสขนาดเล็ก โปรแกรมซอฟต์แวร์ และแอปพลิเคชันที่ครอบคลุมยิ่งขึ้นได้อย่างมีประสิทธิภาพด้วยค่าใช้จ่ายด้านการจัดการน้อยกว่าเครื่องเสมือน (ที่มา: Container Technologies for ARM Architecture: A Comprehensive Survey of the State-of-the-Art)
	2.4.3.6 Container Orchestration
		Container Orchestration คือการปรับใช้และจัดการแอปพลิเคชันที่เป็น Container ที่อยู่ในคลัสเตอร์ที่เชื่อมต่อถึงกัน โดยมีโหนดที่คอยควบคุมการทำงานที่เรียกว่าโหนดมาสเตอร์ (Master node) ซึ่งมีหน้าที่ดูแลคลัสเตอร์และจัดการการปรับใช้คอนเทนเนอร์บนโหนดเวิร์กเกอร์ (Worker node) โดยแต่ละคลัสเตอร์ได้รับการจัดการโดยมีโหนดหลักอย่างน้อยหนึ่งโหนด และยังสามารถขยายไปยังโหนดหลักหลายโหนดได้ ขึ้นอยู่กับข้อกำหนดด้านความพร้อมใช้งานของคลัสเตอร์ เพื่อกำหนดการปรับใช้คอนเทนเนอร์บนโหนดเวิร์กเกอร์ที่เหมาะสมที่สุด (ที่มา: Automotive Container Orchestration: Requirements, Challenges and Open Directions)
	2.4.3.7 Cloud-Init
			Cloud-Init คือการตั้งค่าที่ถูกเตรียมไว้ล่วงหน้าสำหรับการจัดเตรียมเครื่องจำลองใหม่โดยอัตโนมัติ ซึ่งรวมถึงการสร้างข้อมูลประจำตัวผู้ใช้และการตั้งค่าระบบขั้นพื้นฐาน ด้วยการสร้างไฟล์ cloud-config ที่ปรับให้เหมาะกับเครื่องเสมือนแต่ละเครื่องอย่างไดนามิก Cloud-Init จึงสามารถใช้การกำหนดค่าเหล่านี้ได้อย่างมีประสิทธิภาพ ช่วยเพิ่มประสิทธิภาพด้านพลังงาน ความเร็ว และการปรับแต่งกระบวนการจัดเตรียมเครื่องเสมือนได้อย่างมาก (ที่มา: Building a Cloud Infrastructure for Virtual Machine Scheduling in Datacenters)
